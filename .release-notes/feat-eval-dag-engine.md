# Eval 改用评测图运行,评分改成多维度

<!-- release-target: v2 -->

## 新增功能

- 🧪 Eval 现在按「评测图」运行:图的第一个节点决定被评测的产物从哪来——现在跑一次模型、评测一次已经发生过的会话,或者评测磁盘上的产物文件夹;后面每个判定都是图上一个独立步骤。运行详情里能逐步看到哪一步完成、哪一步没有执行以及原因;同一个用例的多个判定并行执行,不再互相等待。评测已有会话或产物文件夹时不会重跑模型,改了评分标准只花判定本身的开销。
- 📐 评分改成多维度:每个评分器归属一个维度(正确性、简洁性、格式……),同一维度内的多个检查先取平均再与其他维度合并,所以给一个维度多加一项检查不会悄悄放大它的话语权。可以按维度或按重要程度设权重、设通过分数线,并要求最低覆盖率——覆盖率不够时即使分数很高也不算通过,避免「四个维度只判了一个」被当成通过。运行详情和运行汇总都会给出每个维度的得分,而不只是一个笼统的总分。
- ✍️ 判定可以由你自己写代码:内联 JavaScript 直接在沙箱里跑,只能看到当前用例的任务、产物和轨迹,没有文件系统、网络和模块;也可以调用外部命令,用例以 JSON 从标准输入进来、判定结果从标准输出回去。一个脚本可以一次给出多个维度的分数。脚本自己出错、超时、退出码非零或输出不是判定结果时,记为无法判定并附上脚本自己的日志,绝不会算成 0 分。外部命令默认不允许执行,需要在设置里明确开启;未开启时这类判定会如实记为未评分。
- 🗂️ 数据集可以是一个文件夹:`dataset.md` 写总览,`cases` 目录下每个 `.json` 一条用例,人和 AI 都能直接读写和逐条修改。数据集页可以导入文件夹、也可以把已有数据集导出成这种格式;再次导入同一个文件夹是更新而不是新建,用例在多次运行之间保持同一身份,方便前后对比。
- 🔗 每条用例会关联到它真实产生的会话,可以直接从用例打开该会话查看完整轨迹。会话还没索引完成时会继续等待一段时间,拿不到就明确标注,不会静默丢失。有了轨迹还可以判定「做事过程」,比如工具调用失败了多少次;产物文件夹没有轨迹,这类判定会明确记为跳过,而不是当成通过。
- 📎 绑定了 Skill 的评测方案在运行时会把该 Skill 的说明随任务一起交给模型,并记录本次实际使用的 Skill 版本;在能观测到使用情况时,还会显示是否真的用到了它,观测不到时如实标注为无法判断而不是判定未使用。
- 🧩 Eval 拆成按对象组织的独立页面:数据集、评分器、评测图、运行各自一页,原来那个把创建流程堆在一起的实验页已移除。执行图页支持新建和编辑图:从调色板拖入节点、连线组装自己的评测流程,连线类型不匹配、缺少来源、成环等问题在保存前就会指出来,校验不通过不允许保存。在画布上加的判定会自动记进这套方案,不需要再去别处勾选一遍。
- 🔌 新增内置「AgentRecall Eval」MCP:AI 可以直接创建和维护评测数据集(整体替换、追加用例,或导入/导出数据集文件夹),并查询评分器、评测方案与运行结果;运行结果会逐用例返回每一步的状态、每个维度的得分和「没产出的原因」,便于区分判为不通过和根本没能判定。默认关闭,可在 MCP 页面开启。

## Bug 修复

- 修复评分器自身无法工作时被记为 0 分的问题。未配置 Runtime 通道、调用失败、返回内容无法解析等情况,现在会标记为无法判定,并从平均分与通过率中排除,不再被当作模型表现差。
- 修复模型完全没有产出时仍然给出 0 分的问题,这类用例现在标记为未评分并说明原因。
- 修复运行被取消后仍然发布一个看起来正常的分数的问题。
- 修复通过率按评分器条目统计导致偏高的问题,现在按用例统计:一个用例要通过,既要总分达到分数线,也要判定的覆盖率达标。
- 修复期望输出缺失时确定性评分器直接判定不通过的问题,现在会说明该用例缺少期望输出,不再把数据集的问题算到模型头上。
- 修复删除数据集或评分器时看不到影响范围的问题,现在会提示有多少评测方案正在使用它;评分器被删除后,引用它的判定会记为跳过而不是让整次运行无法开始。
