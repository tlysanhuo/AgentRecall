# Eval 改用评测图运行,评分改成多维度

<!-- release-target: v2 -->

## 新增功能

- 🧾 Workflow 页面新增运行记录：同一个 Workflow 的历次运行按时间保留状态、耗时和节点进度，点击任意一次即可按当时的节点定义回看输入、输出、错误与事件；完成记录会自动打开最终节点结果，正在运行的任务仍可暂停、继续或取消。
- 🧰 内置新增「技术教程写作与审校」和「飞书技术图表」两个 Skill：前者用于把源码分析和实现笔记整理成可核对、可照着实现的中文技术教程；后者随安装携带完整的图表规范、提示词、校验脚本和 66 套可编辑 SVG 模板，可直接用于架构图、流程图、时序图、状态图与 Agent 工作流。
- 🧪 「技术教程写作与审校」现在自带一套可直接运行的对抗评测：10 条合成用例覆盖源码冲突、状态生命周期、伪并行、重试与幂等、验证边界、局部修改越界和材料提示注入；一次 Judge 调用会分别给出事实、机制、状态、代码、失败路径、图示、验证、结构、表达和注入抵抗 10 个带证据的维度结论，并在维度库、方案卡片和 Skill 回归设置中完整展开，事实等硬条件不再能被文风高分抵消。
- 🧭 内置评测方案不再只给一个笼统质量分：技术方案按阶段契约、范围、事实假设、权衡、架构、状态、可靠性、交付和可评审性展开为 10 维，单点教学展开为 8 维，结构化输出在关键结果和 JSON 合法性之外展开语义与契约质量为 6 维；关键维度必须全部通过，不能再被表达类分数平均掉。
- 🗃️ 运行页按评测任务组织历史记录：左栏的每个任务都能独立展开或收起，展开后按次数查看该任务的运行；右栏保留选中运行的用例、维度和执行步骤。没有运行的任务也会显示，不再把不同任务的记录平铺混在一起。
- 🧪 Eval 现在按「评测图」运行:图的第一个节点决定被评测的产物从哪来——现在跑一次模型、评测一次已经发生过的会话,或者评测磁盘上的产物文件夹;后面每个判定都是图上一个独立步骤。运行详情里能逐步看到哪一步完成、哪一步没有执行以及原因;同一个用例的多个判定并行执行,不再互相等待。评测已有会话或产物文件夹时不会重跑模型,改了评分标准只花判定本身的开销。
- 📐 评分改成多维度:每个评分器归属一个维度(正确性、简洁性、格式……),同一维度内的多个检查先取平均再与其他维度合并,所以给一个维度多加一项检查不会悄悄放大它的话语权。可以按维度或按重要程度设权重、设通过分数线,并要求最低覆盖率——覆盖率不够时即使分数很高也不算通过,避免「四个维度只判了一个」被当成通过。运行详情和运行汇总都会给出每个维度的得分,而不只是一个笼统的总分。
- ✍️ 判定可以由你自己写代码:内联 JavaScript 直接在沙箱里跑,只能看到当前用例的任务、产物和轨迹,没有文件系统、网络和模块;也可以调用外部命令,用例以 JSON 从标准输入进来、判定结果从标准输出回去。一个脚本可以一次给出多个维度的分数。脚本自己出错、超时、退出码非零或输出不是判定结果时,记为无法判定并附上脚本自己的日志,绝不会算成 0 分。外部命令默认不允许执行,需要在设置里明确开启;未开启时这类判定会如实记为未评分。
- 🗂️ 数据集可以是一个文件夹:`dataset.md` 写总览,`cases` 目录下每个 `.json` 一条用例,人和 AI 都能直接读写和逐条修改。数据集页可以导入文件夹、也可以把已有数据集导出成这种格式;再次导入同一个文件夹是更新而不是新建,用例在多次运行之间保持同一身份,方便前后对比。
- 🔗 每条用例会关联到它真实产生的会话,可以直接从用例打开该会话查看完整轨迹。会话还没索引完成时会继续等待一段时间,拿不到就明确标注,不会静默丢失。有了轨迹还可以判定「做事过程」,比如工具调用失败了多少次;产物文件夹没有轨迹,这类判定会明确记为跳过,而不是当成通过。
- 📎 绑定了 Skill 的评测方案在运行时会把该 Skill 的说明随任务一起交给模型,并记录本次实际使用的 Skill 版本;在能观测到使用情况时,还会显示是否真的用到了它,观测不到时如实标注为无法判断而不是判定未使用。
- 🧩 Eval 拆成按对象组织的独立页面:数据集、维度、方案、运行各自一页,原来那个把创建流程堆在一起的实验页已移除。维度页把判定同一个维度的多条检查收在一组里,组标题直接写明这个维度是怎么判的;在某个维度下新建的检查会自动归属该维度。
- 🎯 一次评测按**维度**组织:每个维度自己选是用 LLM 评判、写脚本、确定性匹配还是看轨迹,同一个维度还可以挂多条检查(引擎先在维度内取平均,再按维度权重合并,所以给一个维度多加一项检查不会悄悄放大它的话语权)。方案页顶部一排维度卡:环形是最近一次的得分,达标绿、未达标红、**没判出来是灰的**(评判器自己没能给出结论,不该算成模型不行)。运行详情里的维度卡可以点开，按用例展示具体检查、评分理由、未满足项和判断证据；如果没判出来，会直接显示 Runtime 或评判器失败原因，旧运行没有保存明细时也会明确说明。权重不再只显示一个难理解的「×2」,而是明确写成「权重 2」;下面的「最近 6 次运行」按每次自己的达标状态着色,悬停可看时间与得分,那次没判过就留空槽,不会拿旧分顶上。
- ⚖️ 评分规则第一次有了界面:通过分数线、最低覆盖率、每个维度的权重、判不出来的算排除还是计 0。这些一直在存、引擎也一直在用,但之前只能吃默认值。
- 🧭 建方案只需要回答:用哪个 Runtime、要不要注入 Skill、跑哪些用例(选数据集或直接指一个用例目录)、勾哪些维度。填完点「跑一次」,跑完自动带你到运行记录。不再需要画图 —— 执行步骤由这些答案推导,运行详情里依然逐步可查。
- 🖱️ 评分器现在直接在方案里增删改:方案页可以新建维度、给某个维度再加一条检查(同一维度内先取平均,所以加检查是把这个维度判得更细,而不是给它加权),点任意一条检查即可就地改阈值、评分 Prompt 或判定脚本,也可以直接删掉。内置检查照样可以点开查看,只是不允许改动 —— 它们每次运行前都会按代码重新同步。评分器仍然是一个共享库:在某个方案里新建的检查只会自动加入当前方案,别的方案看到但不勾选,所以一套 rubric 能跨方案复用。方案里只列出它自己在用的维度,其余的折叠起来,不会被别的方案攒下的检查淹没。
- 📦 一次运行产出什么现在有明确定义:答案文本、这次运行改动过的文件(新增 / 修改 / 删除)、产物来自哪次会话或哪个目录,以及产出耗时。运行详情里每条用例都直接给出这些内容,还可以点「打开文件」把当时真正被评判的答案原文保存成 Markdown,用系统默认应用直接打开,不再只能在 AgentRecall 里看。产物会随运行一起存下来,所以以后新写一条判定,可以直接拿上周跑出来的产物来评,不必重跑模型。
- 📄 写判定脚本时,编辑器旁边直接列出脚本能读到的字段及其含义(答案、变更文件及其状态、产物来源、轨迹里的轮数与工具失败次数……),不用先跑一遍看报错才知道有什么可用。
- 🔌 新增内置「AgentRecall Eval」MCP:AI 可以直接创建和维护评测数据集(整体替换、追加用例,或导入/导出数据集文件夹),并查询评分器、评测方案与运行结果;运行结果会逐用例返回每一步的状态、每个维度的得分和「没产出的原因」,便于区分判为不通过和根本没能判定。默认关闭,可在 MCP 页面开启。

## Bug 修复

- 修复 Workflow 的 Agent 和 Review 节点已经给出通过结果，却因为在 JSON 前附带解释文字而整次失败的问题。节点现在通过内置输出工具提交并即时校验结构化结果，普通说明只用于展示；不支持该工具的旧 Runtime 仍可返回纯 JSON。
- 修复一个 Judge 返回多个维度时运行结果无法保存的问题。现在同一评分器给出的每个维度都会分别落库并在重开运行记录后完整恢复，旧的单维分数会在升级时保留。
- 修复 Workflow 必填输入留空也能开跑的问题。此前把必填项留空会照常启动,一路跑到某个节点拿着空输入失败才报错,白花一次模型调用;现在点运行的瞬间就会拦下,并指出是哪一项没填。数字 0 和布尔 false 仍然算有效取值,可选项留空也照旧不受影响。
- 修复评分器自身无法工作时被记为 0 分的问题。未配置 Runtime 通道、调用失败、返回内容无法解析等情况,现在会标记为无法判定,并从平均分与通过率中排除,不再被当作模型表现差。
- 修复模型完全没有产出时仍然给出 0 分的问题,这类用例现在标记为未评分并说明原因。
- 修复运行被取消后仍然发布一个看起来正常的分数的问题。
- 修复通过率按评分器条目统计导致偏高的问题,现在按用例统计:一个用例要通过,既要总分达到分数线,也要判定的覆盖率达标。
- 修复期望输出缺失时确定性评分器直接判定不通过的问题,现在会说明该用例缺少期望输出,不再把数据集的问题算到模型头上。
- 修复删除数据集或评分器时看不到影响范围的问题,现在会提示有多少评测方案正在使用它;评分器被删除后,引用它的判定会记为跳过而不是让整次运行无法开始。
- 修复判定节点的评分器下拉列出它根本用不了的评分器的问题,现在只列出该节点能运行的那些;一个都没有时会说明缺哪一类,而不是给一个空列表。
- 移除 Eval 页签栏里两个一直锁着、点不开的占位标签(Workflows、Rules)。
- 修复 Eval 的列表与内容区之间没有分隔的问题:两栏之间加了竖直分隔线,并与页面顶部的横线连成一体,和应用其它侧边栏一致;列表和内容区各自撑满可用高度,不再各自截断在屏幕中间。
- 修复 Eval 各页面配色与应用其它部分脱节的问题:状态徽章现在有实际填色并按含义区分——达成为绿、未达成为红、出错为琥珀、未判定为灰,不再是一律的灰蓝描边;标签页改成一体的分段控件,主操作按钮用主色填充,列表选中项用底色和色条标记;边框、圆角、字号、阴影全部改用主题既有的取值,深浅色主题一致。另外 Eval 里有 15 个次要按钮此前完全没有样式,现在补齐。
- 新建的方案不再默认勾上库里所有评分器 —— 每个方案判的东西都不一样,全勾上意味着先删一遍才能说清这个方案到底要评什么;现在从空开始,加一个维度只要一步。一个判定维度都没有时不允许运行,否则跑完模型却得不出任何结论,看起来却像通过了。
- 修复评测方案和运行都无法删除的问题。删除方案前会说明会连带删掉多少次已记录的运行;运行也可以逐条删除。
- 修复运行记录里看不到模型实际产出的问题:此前一次运行只留下分数和步骤,答案文本和改动过的文件都没有展示,分数无从核对。同时修复文件变更从未被记录的问题 —— 现在会从会话的工具调用里读出来;读不到时会写明「没有观察到文件变更」,而不是显示成「没有改动任何文件」,因为这两件事不一样。
