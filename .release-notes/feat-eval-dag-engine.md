# Eval 实验改用执行图运行

<!-- release-target: v2 -->

## 新增功能

- 🧪 Eval 实验现在按执行图运行:任务、Skill 注入、Agent 执行、会话关联、每个评分器都是图上的一个独立步骤,运行详情里能逐步看到哪一步完成、哪一步没有执行以及原因;同一个用例的多个评分器并行执行,不再互相等待。
- 🔗 回归评测的每条用例会关联到它真实产生的会话,可以直接从用例打开该会话查看完整轨迹。会话还没索引完成时会继续等待一段时间,拿不到就明确标注,不会静默丢失。
- 📎 绑定了 Skill 的评测方案在运行时会把该 Skill 的说明随任务一起交给 Agent,并记录本次实际使用的 Skill 版本;在能观测到使用情况时,还会显示 Agent 是否真的用到了它,观测不到时如实标注为无法判断而不是判定未使用。

- 🧩 Eval 新增独立的「执行图」页面,并支持**新建和编辑图**:从调色板拖入节点、连线组装自己的评测流程,连线类型不匹配、缺少来源、成环等问题在保存前就会指出来,校验不通过不允许保存。没有自定义图的实验仍按默认形状运行。
- 🔌 新增内置「AgentRecall Eval」MCP:Agent 可以直接创建和维护评测数据集(整体替换或追加用例),并查询评分器、实验与运行结果;运行结果会逐用例返回每一步的状态和「没产出的原因」,便于区分评判器判为不通过和评判器根本没能运行。默认关闭,可在 MCP 页面开启。
- 🗂️ Eval 拆成按对象组织的独立页面:数据集、评分器、执行图、运行各自一页,原来那个把创建流程堆在一起的实验页已移除。数据集页支持批量粘贴导入(JSON 数组,或每行制表符分隔的输入/期望输出/上下文),并可以直接填写交给模型评判器的上下文——这两件事之前都做不到;删除数据集或评分器前会提示有多少实验正在使用它,切换页面时也会提示未保存的修改。评分器页在选择判定方式的位置就说明它需要什么,例如模型评判缺少 Runtime 通道时用例会记为未评分而不是不通过。

## Bug 修复

- 修复评分器自身无法工作时被记为 0 分的问题。未配置 Runtime 通道、调用失败、返回内容无法解析等情况,现在会标记为无法判定,并从平均分与通过率中排除,不再被当作 Agent 表现差。
- 修复 Agent 完全没有产出时仍然给出 0 分的问题,这类用例现在标记为未评分并说明原因。
- 修复运行被取消后仍然发布一个看起来正常的分数的问题。
- 修复通过率按评分器条目统计导致偏高的问题,现在按用例统计:一个用例只有全部评分器都通过才算通过。
- 修复期望输出缺失时确定性评分器直接判定不通过的问题,现在会说明该用例缺少期望输出,不再把数据集的问题算到 Agent 头上。
